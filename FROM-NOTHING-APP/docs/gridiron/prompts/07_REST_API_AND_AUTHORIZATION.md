# Prompt 07 — FOCUS-integrated REST, OpenAPI, MCP and role scope

```text
Build /api/v1/gridiron/* operations by extending existing focus/web/operations.py registry in a dedicated handler module imported at routes registration, respecting the current API envelope, error contract, existing grants/CSRF, identity context, worker queue and operation-generated OpenAPI/MCP. All GETs are strictly projections of persisted or fixture-frozen current sports snapshots and NEVER pull employee timeclock data, compute score, or simulate. All POSTs require CSRF, same-origin, strict schema, idempotency key, authorized role and durable worker; return 202 and a pollable run id. Feature flag off returns a clear typed blocked/unavailable state with no information leak.

Required GET: /api/v1/gridiron/context, /me, /teams, /season/{season_id}, /matches/{match_id}, /standings?season, /weeks/{week_id}/lineups, /diagnostics (admin only). Player `/me` derives game person ID only from trusted server identity mapping, never a client-supplied badge or person ID. Team lineup views show positions, aliases, rating display where opt-in permits, and a 'best-fit selected' rationale; never raw manufacturing metrics of other workers. Detailed own score components are private. For live insufficient roster give ROSTER_INCOMPLETE and exact safe eligible count (suppress small cohorts); don't silently fill. Only consenting team members may be visible; correct team membership frozen and validated server-side regardless of query params.

Required POST: /enroll (self opt-in/out), /weeks/{id}/freeze-ratings (policy owner/administrator), /weeks/{id}/build-lineups (authorized worker), /matches/{id}/simulate (league operator), /matches/{id}/revise (reviewed correction). Decide exact grants with existing security conventions; independent approval for live processing. Never allow a player to submit a labor score or override their position rating from browser. Don't automatically expose new personal endpoints in MCP; explicitly configure appropriate read-only resources with identical scope or keep MCP off for this domain. Version JSON schemas and document contract in README.

Test scope-before-fetch for every endpoint, permission matrix across fixture personas, malicious same-team/cross-team ids, IDOR, opt-out midseason, aliases in wrong team's lineup, anonymous access, CSRF, MIME, invalid/duplicate idempotency, pagination/cursors, base-path, read-only GET, auto-generated OpenAPI and disabled-mode. No insecure debug route or real roster data in publicly hosted fixture deployment.
```
